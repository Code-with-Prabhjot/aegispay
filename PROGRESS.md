- 2026-11-05 — Task 20 (branch `fix/audit-security-and-settlement`), from a code audit of main at `4bac174`:
  - The buyer's test suite is committed in the agreement (`test_suite`, stored with its SHA-256); submitters can no longer supply the tests, and `semantic_score` overrides are mock-only. Before this a worker could submit always-passing tests and be paid in full.
  - The test file is scanned like the deliverable, and untrusted code only runs where isolation exists: Python needs Docker, Node/JS has no isolated runner, so outside mock mode both are refused unless `ALLOW_UNISOLATED_SANDBOX` is set (never with real funds). Scanner bypasses (importlib, pickle, dynamic import, `require` aliasing, `process`, constructor chains) are blocked.
  - Every route except `/health` and the signed webhook needs `X-API-Key` (`API_AUTH_KEY`); outside mock mode they return 503 until it is set. The WebSocket checks the key and Origin. Sweeper clock overrides, vault allowance refresh and demo-vault creation are mock-only.
  - A failed capture/void or a crashed arbiter no longer strands funds: an arbiter crash voids the hold, `POST /contracts/{id}/settlement/retry` re-drives a pending capture/void, and an evaluation silent for 10 minutes can be aborted.
  - Sweeper: never voids a real hold before a new one exists, never stores a fabricated authorization id, reports failed voids/renewals (`failed_agreements`) instead of marking them refunded, keeps `created_at` (hold age comes from `authorized_at`), uses a new PayPal request id per renewal, shares the orchestrator lock, and `/sweeper/status` lists stranded settlements.
  - Vault: open holds count against the daily budget (reserved at creation, released on settle/void/expiry, including webhook recovery); vaulted orders use `payment_source.paypal.vault_id`.
  - A2A: signed terms now include the worker's payout email and the test-suite hash; `did:key` agent ids must match the signing key; named ids are mock-only; `REQUIRE_A2A_SIGNATURES` rejects unsigned contracts.
  - Partial-capture math uses exact fractions (67 of 24,000 amounts were a cent low). `paypal_webhooks.py` no longer claims RSA verification, drops its magic signature strings and unused dispatcher. Arbitration no longer holds the orchestrator lock.

- 2026-11-09 — Task 21 (branch `fix/audit-main-bugs`), from an audit of main at `c1964a9`:
  - `POST /mcp/rpc` was also mounted at the root, outside the API key check, so anyone could create contracts and submit code with no key. Only `/api/v1/mcp/rpc` remains.
  - Sandbox runner: the scrubbed environment dropped the user site-packages (on Windows they live under `%APPDATA%`), so pytest could not import, and the 5s limit included interpreter/pytest startup (6-8s on a slow machine). Both scored as failing tests and voided good work. The child now gets the interpreter's site-packages on `PYTHONPATH`, a watchdog conftest times only the tests (`SANDBOX_TEST_TIMEOUT_SECONDS`, default 15s; startup gets a 60s backstop), and a runner that cannot run raises `SandboxInfrastructureError`, which voids as an arbiter failure ("not a verdict on the worker's code") instead of a 0 score.
  - A payout that failed right after the capture left the contract in `PAYPAL_CAPTURED` with no way out (both retries refused it, the sweeper did not list it) and returned 502. The capture now stands, `POST /contracts/{id}/payout/retry` dispatches it (attempt 1 reuses the PayPal request ids, so it cannot pay twice), and `/sweeper/status` lists `unpaid_captures`.
  - `/ledger/balance` and `verify_balance_conservation()` summed the same list twice, so they could never report an imbalance. They now replay deposits + journal and compare with the running balances (`audit_balances()`).
  - `/a2a/negotiate` with `auto_sign` swallowed every error and returned an agreement id for a contract that was never created (wrong signed payload, a non-existent field and attribute). It now signs the canonical terms with fresh `did:key` identities, creates and locks the contract, returns its authorization id, is mock-only, and reports failures.
  - Vault: outside mock mode `POST /vaults` registers new vaults but can no longer overwrite one (that zeroed its spend counter), and `/vault/setup-token` (which fabricated an "APPROVED" vault without PayPal) is mock-only. Breaker reset and freeze/unfreeze stay available to key holders as operator actions. `/vault/velocity` for an unknown buyer is 404 instead of "allowed". Releasing a hold reserved in an earlier 24h window no longer eats into the current window.
  - Sweeper reads active and stranded contracts with a state query and no row limit (it used the newest 1000, dropping the oldest holds first).
  - `PAYPAL_MODE` other than mock/sandbox/live is rejected at startup (a typo used to select the live API). CORS and the WebSocket origin check use `CORS_ALLOWED_ORIGINS`. `/health` actually queries the database.
  - Dashboard: `src/middleware.ts` adds `X-API-Key` (from the server-side `API_AUTH_KEY`) to proxied `/api/v1` requests; the WebSocket goes through the same proxy and authenticates with a 60s HMAC ticket from `GET /api/v1/ws-ticket` (browsers cannot set WebSocket headers). Verified with `next start` against a keyed backend: REST, WebSocket snapshot, forged/expired tickets and foreign origins rejected.
  - Deploy: frontend image built (invalid `COPY ... || true` removed; `BACKEND_URL` is a build arg because Next bakes the rewrite target at build time; bare `host:port` accepted), SQLite at `/app/data` so the compose volume persists it, backend listens on `$PORT`, Render passes `hostport` and shares the generated key with the dashboard, Fly mounts a volume. Added `.github/workflows/ci.yml` (pytest, frontend lint + build).

## Known gaps
- Outside mock mode untrusted Python runs only in Docker (build `sandbox/`), and there is no isolated Node/TypeScript runner yet, so JS/TS submissions are refused there.
- The dashboard adds `X-API-Key` server-side, so anyone who can open the dashboard can use the API through it. Put the dashboard behind access control before exposing it publicly. A WebSocket ticket can be reused until it expires (60s).
- The Docker images and the Render/Fly configs have not been built or deployed from this branch (no Docker available where the fixes were made); the Next proxy, middleware and WebSocket ticket were verified with `next start`.
- Server-side `auto_sign` uses a placeholder test suite (mock mode only); real agreements must commit the buyer's suite via `POST /contracts`.
- The ledger records money arriving (demo funding per contract) but not payout money leaving PayPal; `worker_payable` keeps the net payout.
- Not yet run against live PayPal: the vaulted-order shape (`payment_source.paypal.vault_id`) and `/reauthorize`.
- Named (non-`did:key`) agent ids cannot be bound to a key outside mock mode, and there is no agent-identity registry.
- A declined capture still leaves the PayPal hold and the vault reservation in place until the hold lapses.
- The sweeper voids non-vaulted holds at 70 hours although PayPal honors them for 72.
- A void PayPal rejects because the authorization was already voided leaves that contract in the sweeper's `failed_agreements` for an operator.
- `DAILY_SPEND_LIMIT_MICROS` is not enforced anywhere.
- Only the sqlite driver is implemented (`postgresql://` URLs raise), although `schema.sql` is Postgres-compatible.
- The real PayPal flow needs a buyer-approval step (Orders v2 authorize); no live sandbox test has been run.
- Capture-declined leaves the authorization hold unreleased (design decision pending).
- Docker runner and Claude judge are only tested with mocks.
- Webhook signature verification has only run against stubs. The parsed event is re-serialized for `verify-webhook-signature`, so confirm with a real sandbox delivery that PayPal accepts it.
- The frontend has not been exercised in a browser (build/lint only).
- `npm audit` reports warnings for frontend dependencies.
